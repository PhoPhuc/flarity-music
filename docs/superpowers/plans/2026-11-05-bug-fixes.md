# Bug Fixes from Full-Repo Review Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix every defect listed in the 2026-11-05 review of flarity-music (backend, frontend, build and security config).

**Architecture:** Backend fixes stay in the existing Rust modules (`lib.rs`, `commands.rs`, `db.rs`, `covers.rs`, `telemetry.rs`); pure logic gets `#[cfg(test)]` unit tests. Frontend fixes are local to the affected components/hooks. Config fixes touch `tauri.conf.json`, `package.json`, `.cargo/`, Android Gradle and `.gitignore`.

**Tech Stack:** Rust (Tauri 2, rusqlite, url), TypeScript/React 19, Vite, Gradle (Kotlin DSL).

**Spec:** the review findings of this session (see the chat transcript of 2026-11-05).

## Global Constraints

- Build verification: `cargo test` and `cargo check` in `src-tauri` (Linux target via `CARGO_BUILD_TARGET=x86_64-unknown-linux-gnu`), `npx tsc -p tsconfig.app.json --noEmit`, `npx oxlint src`, `npx vite build`.
- No secrets in the repository.

## Review Focus

1. Feeding a non-URL or `-`-prefixed string to yt-dlp must not execute options. Test: `validate_media_url("--exec=id")` is `Err`.
2. A scan with an empty or failed cover query must not delete covers. Test: `cleanup_orphan_covers` on a connection with no tables returns `Err` and deletes nothing.
3. Re-scanning must not overwrite a manual metadata edit. Test: `save_tracks` after `update_track_metadata` keeps the edited title.
4. A move with an unexpected folder layout must not move files outside the library. Test: `plan_move_target` returns `None` for `D:\song.mp3`.
5. Opening a URL with a `file:` or custom scheme must be refused. Test: `is_allowed_external_url("file:///etc/passwd")` is false.

## Tasks

Tasks are executed in order in this session. Each task ends with `cargo test` / `tsc` passing and a commit.

1. Backend safety: exit behaviour (lib.rs), cover cleanup guard and error propagation (covers.rs), DB persistence flag (db.rs, lib.rs).
2. Backend data integrity: scan upsert preserves manual edits and LRC/MV links (db.rs), migration order (db.rs, covers.rs), move_file target validation and id rekey (commands.rs, db.rs), delete ordering (commands.rs).
3. Backend commands: yt-dlp URL validation and removal of `--no-check-certificates` (commands.rs), `open_external_url` scheme check (commands.rs), `%` in filenames (commands.rs), reveal-in-folder on macOS/Linux, `scan_folder` in `spawn_blocking` with cached directory listings (commands.rs), telemetry flush on pause/heartbeat (commands.rs, telemetry.rs, lib.rs).
4. Frontend: TypeScript errors (60 unused/type-import issues that break `npm run build`), stable telemetry hook, single Audio instance, telemetry calls, version from package.json, CSP and asset scope.
5. Config and security: Android signing from untracked `keystore.properties`, untrack `.jks`, personal paths removed from `package.json` and `.cargo/config.toml`, version check script.

Test-first is applied to every pure function (unit tests in the same Rust file). Config and UI changes are verified by the build commands listed above.
